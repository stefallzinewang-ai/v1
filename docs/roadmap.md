# 路线图与里程碑

> 系统很大，原则是**先把「AI→光模块」这一条主线端到端跑通**，再横向扩展。
> 每个阶段都应是「可运行、可验证」的闭环，而非半成品堆叠。

## 阶段 0 · 架构与骨架 ✅（当前）
- [x] 八层分层架构与文档（`docs/`）
- [x] 代码包骨架与统一接口（`src/alpharadar/`）
- [x] 示例主线配置（`config/themes/ai_optical_module.yaml`）
- [x] CLI 骨架与冒烟测试

**交付物**：可 `python -m alpharadar.cli --help`；分层接口清晰，可分别填充。

## 阶段 1 · 数据打通（data）🚧 进行中
- [x] 标准 schema 与代码工具（`data/schema.py`）：统一列定义、symbol/secid 转换。
- [x] `EastmoneySource`：日线行情、指数行情、业绩报表（含公告日）、行业成分；
      解析逻辑（纯函数）与 HTTP 抓取分离，解析逻辑已离线样本单测。
- [x] `data/http.py`：限速 + 指数退避重试（4xx 不无谓重试）。
- [x] `store.py`：parquet 按年分区读写 + SQLite 水位线（往返已测）。
- [x] `ingest.py`：增量更新（按水位线）+ 行情一致性校验。
- [x] CLI `sync <theme>`：按主线候选股采集行情/财务并落地。
- [ ] 宏观 `macro()` 接入（东方财富 datacenter）。
- [ ] DuckDB 查询加速（可选优化）；缓存原始响应（可选）。
- [ ] 在能联网的机器上实跑：拉取光模块板块全历史，校验数据质量。

**验证**：解析/存储/增量逻辑已离线测试通过（13 项）；真实联网采集需在可访问
东方财富的机器上运行 `alpharadar sync ai_optical_module`（云环境因白名单代理被拦截）。

## 阶段 2 · 市场状态（regime）🚧 进行中
- [x] 四维状态打标签规则版 baseline（纯函数，合成数据离线单测）：
      趋势(均线位置+斜率) / 风格(成长vs价值) / 风险偏好(小盘vs大盘) / 流动性(占位)。
- [x] 趋势多数表决平滑，抑制抖动；各维度缺数据时优雅降级。
- [x] 指数 secid 修正 + `sync` 自动采集指数 + CLI `regime` 命令。
- [ ] 流动性维度待宏观 `macro()` 接入后实现 easing/tightening。
- [ ] 回放历史，画出 15 年状态时间线，人工核对关键拐点（如 2015、2018、2020）。

**验证**：分类逻辑已离线测试（12 项）；CLI `regime` 已用合成指数端到端跑通。
历史回放核对需真实指数数据（在可联网机器 `sync` 后运行）。

## 阶段 4 · 主线映射（theme）🚧 进行中
- [x] YAML 产业链加载与访问器（瓶颈环节、关键变量、景气权重、板块代码）。
- [x] 激活判断 `evaluate()`：市场状态 / 行业景气 / 政策支持 三道门，带可解释理由。

正确激活，候选池从 3 只种子自动增强到 4 只。

---

## 优先级建议

如果要尽快看到价值，推荐顺序：**阶段 1 → 2 → 4 → 5 → 6 → 3/7**。
即先打通数据与状态，把主线和规律挖掘这两个「最有信息量」的环节做出来，
再补全因子细节与报告美化。

## 风险与注意

- 🔴 **过拟合**是头号风险，阶段 5 的样本外纪律决定系统成败。
- 🟠 数据源稳定性：AKShare 接口可能变动，需在阶段 1 把缓存与重试做扎实。
- 🟠 幸存者偏差：阶段 1 务必纳入退市股，否则后续全部失真。
- 🟢 范围蔓延：克制住「一次做全市场」的冲动，先把一条主线做到极致。
