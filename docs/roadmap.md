# 路线图与里程碑

> 系统很大，原则是**先把「AI→光模块」这一条主线端到端跑通**，再横向扩展。
> 每个阶段都应是「可运行、可验证」的闭环，而非半成品堆叠。

## 阶段 0 · 架构与骨架 ✅（当前）
- [x] 八层分层架构与文档（`docs/`）
- [x] 代码包骨架与统一接口（`src/alpharadar/`）
- [x] 示例主线配置（`config/themes/ai_optical_module.yaml`）
- [x] CLI 骨架与冒烟测试

**交付物**：可 `python -m alpharadar.cli --help`；分层接口清晰，可分别填充。

## 阶段 1 · 数据打通（data）
- [ ] 实现 `AkshareSource`：日线行情、财务摘要、宏观指标、行业成分。
- [ ] `store.py`：parquet + DuckDB 读写，SQLite 水位线。
- [ ] `ingest.py`：增量更新、限速重试、缓存。
- [ ] 拉取光模块板块 + 宽基指数 + 核心宏观，落地本地存储。

**验证**：能离线查询任意股票 15 年行情与历年财务，数据通过一致性校验。

## 阶段 2 · 市场状态（regime）
- [ ] 实现四维状态打标签（规则版 baseline）。
- [ ] 回放历史，画出 15 年状态时间线，人工核对关键拐点（如 2015、2018、2020）。

**验证**：历史状态划分与市场常识吻合，状态切换不抖动。

## 阶段 3 · 因子与基本面（factors + fundamental）
- [ ] 实现五大类核心因子，统一预处理管线。
- [ ] 因子有效性检验：IC / 分层回测。
- [ ] 公司基本面打分模块。

**验证**：核心因子 IC 显著且稳定；基本面打分在样本上区分度合理。

## 阶段 4 · 主线映射（theme）
- [ ] YAML 产业链加载与校验。
- [ ] 主题触发逻辑 + 瓶颈环节景气打分 + 候选池补全。

**验证**：输入「AI」能正确收敛到光模块环节与候选股池。

## 阶段 5 · 规律挖掘（mining）⭐ 核心
- [ ] Walk-forward 训练框架（严格无未来函数）。
- [ ] 分市场状态训练因子权重，产出 `Pattern`。
- [ ] 防过拟合全套校验（含退市股、交易成本、样本外）。

**验证**：样本外 IR 为正且稳健；不同状态权重有经济解释力。

## 阶段 6 · 选股 + 回测（selection + backtest）
- [ ] 加权融合输出 Top 1~2。
- [ ] Point-in-time 事件回放回测，统计收益/胜率/回撤。

**验证**：端到端回测在样本外跑赢基准，逻辑链完整可追溯。

## 阶段 7 · 报告（report）
- [ ] Jinja2 模板渲染研究报告（Markdown/HTML）。
- [ ] 每个结论标注数据出处与分项得分。

**验证**：针对「AI→光模块」生成一份完整、可读、可追溯的研究报告。

## 阶段 8 · 扩展（后续）
- [ ] 横向扩展更多主线（半导体、医药、新能源…）。
- [ ] Streamlit/FastAPI 前端可视化。
- [ ] 政策文本 NLP 自动抽取。
- [ ] 定时任务与增量更新自动化。

---

## 优先级建议

如果要尽快看到价值，推荐顺序：**阶段 1 → 2 → 4 → 5 → 6 → 3/7**。
即先打通数据与状态，把主线和规律挖掘这两个「最有信息量」的环节做出来，
再补全因子细节与报告美化。

## 风险与注意

- 🔴 **过拟合**是头号风险，阶段 5 的样本外纪律决定系统成败。
- 🟠 数据源稳定性：AKShare 接口可能变动，需在阶段 1 把缓存与重试做扎实。
- 🟠 幸存者偏差：阶段 1 务必纳入退市股，否则后续全部失真。
- 🟢 范围蔓延：克制住「一次做全市场」的冲动，先把一条主线做到极致。
