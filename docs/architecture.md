# 架构总览

> 本文是系统的「地图」。建议先读这一篇，再按需深入 `data-model.md`（数据）、
> `methodology.md`（算法方法论）、`roadmap.md`（实现路线）。

## 1. 设计哲学

整个系统围绕一个核心信念展开：

> **股票上涨 = 「公司在产业链中的位置」 × 「行业景气」 × 「宏观/政策环境」 × 「当前市场状态」 的共振。**

因此系统不是一个「打分器」，而是一条**自上而下、层层收敛**的推理流水线。
每往下一层，候选范围就收窄一次，最终从 5000+ A 股收敛到 1~2 家，并**保留每一步的理由与数据出处**，让结论可解释、可追溯、可回测。

四个关键名词（贯穿全系统）：

| 名词 | 含义 |
|------|------|
| **市场状态 (Regime)** | 当前市场处于哪种环境：牛/熊/震荡、成长/价值占优、风险偏好高/低。 |
| **主线 (Theme / Mainline)** | 一条产业逻辑链，如「AI → 数据传输 → 光模块」。 |
| **瓶颈环节 (Bottleneck)** | 主线上最稀缺、最受益、最能涨价/放量的环节（光模块）。 |
| **共性规律 (Pattern)** | 从 15 年历史归纳出的「某市场状态下，会涨的股票具备的因子特征」。 |

## 2. 八层分层架构

数据自下而上流动，决策自上而下收敛。

```
                 ┌────────────────────────────────────┐
   输出/解释 ←──  │ 8. report      研究报告 + 候选 + 理由 │
                 ├────────────────────────────────────┤
   验证      ←──  │ 7. backtest    15 年历史回测验证规律 │
                 ├────────────────────────────────────┤
   收敛      ←──  │ 6. selection   综合打分 → 1~2 家     │
                 ├───────────┬───────────┬─────────────┤
   评分维度  ←──  │3. mining  │4. theme   │5.fundamental│
                 │ 规律/因子 │ 产业链映射 │ 公司基本面  │
                 ├───────────┴───────────┴─────────────┤
   环境判断  ←──  │ 2. regime      当前处于什么市场状态  │
                 ├────────────────────────────────────┤
   原料      ←──  │ 1. data        行情/财务/宏观/行业   │
                 └────────────────────────────────────┘
```

### 第 1 层 · 数据层 `data`
统一采集并存储四类「关联数据」：行情、财务、宏观、行业（及政策事件）。
对上层屏蔽数据源差异，提供干净、对齐、可复用的 DataFrame。
→ 详见 [`data-model.md`](data-model.md)。

**关键模块**
- `data/sources/` — 各数据源适配器（AKShare 为主，Tushare/baostock 可选），实现统一 `DataSource` 接口。
- `data/ingest.py` — 采集编排：增量更新、重试、限速、缓存。
- `data/store.py` — 存储抽象：时间序列走 parquet/duckdb，元数据走 SQLite。

### 第 2 层 · 市场状态识别 `regime`
输入宏观指标 + 指数行情，输出当前所处的「市场状态」标签。
这是整个系统的「开关」：不同状态下，第 3 层会启用不同的规律。
→ 方法见 [`methodology.md` §市场状态](methodology.md)。

**输出示例**
```python
RegimeState(
    trend="bull",            # bull / bear / range
    style="growth",          # growth / value / balanced
    risk_appetite="high",    # high / neutral / low
    liquidity="easing",      # easing / neutral / tightening
    as_of="2026-06-06",
)
```

### 第 3 层 · 规律挖掘 `mining`
**系统的「大脑」**。用 15 年历史，按市场状态分组，挖掘「会上涨的股票」的因子共性，
产出一组**带权重、带适用状态**的因子模型（Pattern）。线上运行时直接调用已训练好的 Pattern。
→ 方法见 [`methodology.md` §因子与规律挖掘](methodology.md)。

### 第 4 层 · 主线映射 `theme`
把抽象主题落到具体股票池的**产业链知识库**。
读取 `config/themes/*.yaml`，回答：「AI 主题下，瓶颈环节光模块对应哪些股票？关键变量是什么？」
这一层是**配置驱动 + 数据增强**：人工维护产业链骨架，数据自动补全成分股与权重。

### 第 5 层 · 公司基本面 `fundamental`
对候选股票池里的每家公司，按各季度财务指标打分（成长、盈利质量、产能、估值分位等）。
回答：「在光模块这个环节里，谁的业绩兑现度最高、估值还没透支？」

### 第 6 层 · 选股 `selection`
**汇流层**。把第 3/4/5 层的分数按市场状态加权融合，输出最终候选（默认 Top 1~2），
并附带每一项得分的明细，供报告层解释。

### 第 7 层 · 回测 `backtest`
用 15 年历史**事件回放**：在每个历史时点，只用当时可得的数据跑完整流水线，
统计候选股的后验收益、胜率、最大回撤，验证「规律」是否真的有效（防止过拟合/未来函数）。

### 第 8 层 · 报告 `report`
把整条逻辑链渲染成人类可读的研究报告（Markdown/HTML），
每个结论都标注数据出处与得分，做到「可解释、可追溯」。

## 3. 数据流（一次完整运行）

```
              ┌─────────┐
config/themes │ 主题选择 │  ← 可由用户指定，或由 regime+行业景气自动推荐
              └────┬────┘
                   ▼
[1 data] ──→ [2 regime] ──┐
                          ▼
                    [3 mining] 选出当前状态下生效的因子模型
                          │
   [4 theme] 主题→瓶颈→股票池 ─┐
                              ▼
                   [5 fundamental] 对股票池逐一打分
                              ▼
                      [6 selection] 加权融合 → Top 1~2
                              ▼
                      [8 report] 输出研究报告
                              ▲
                      [7 backtest] 离线验证（不在每次运行链路上）
```

## 4. 关键设计原则

1. **可解释 > 黑箱**：每个候选必须能回答「为什么是它」，得分可拆解到因子级。
2. **无未来函数**：任何时点只能用该时点已发布的数据；回测严格 point-in-time。
3. **配置与代码分离**：产业链、因子权重、状态阈值都走 YAML，便于迭代而不改代码。
4. **数据源可插拔**：统一 `DataSource` 接口，换源不影响上层。
5. **分层可独立测试**：每层输入输出是明确的数据结构，可单独 mock 数据做单测。
6. **先窄后宽**：先把「AI→光模块」这一条主线端到端跑通，再横向扩展到更多主线。

## 5. 技术选型

| 关注点 | 选择 | 理由 |
|--------|------|------|
| 语言 | Python 3.10+ | 数据科学生态最成熟 |
| A股数据 | AKShare（主） | 免费、覆盖全、社区活跃；Tushare/baostock 备选 |
| 时序存储 | parquet + DuckDB | 本地、列存、查询快、零运维 |
| 元数据 | SQLite (SQLAlchemy) | 轻量、零部署 |
| 建模 | pandas + scikit-learn | 因子计算与统计建模 |
| 配置 | YAML | 人类可读、Diff 友好 |
| 报告 | Jinja2 + Markdown/HTML | 模板化、易导出 |
| 入口 | CLI（argparse） | 先 CLI，后续可加 Streamlit/FastAPI 前端 |

## 6. 不做什么（边界）

- ❌ 不做交易执行 / 下单 / 实盘对接。
- ❌ 不做高频 / 日内策略，定位**中长期主题投资**（季度级调仓）。
- ❌ 不提供投资建议；输出仅为研究结论，决策与盈亏由使用者自负。
